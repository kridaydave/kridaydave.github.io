FILE ORGANIZER MCP · CASE STUDY TYPESCRIPT · MCP · V5.0.0

One call instead of twenty

GitHub

File Organizer MCP is a local-first filesystem server for LLM agents, and my most-used open source project with 43 stars, six forks, and enough real usage to force four major versions. Its core bet: generic filesystem MCP servers make assistants chain twenty primitive calls (read, write, rename, mkdir…), and every extra call costs tokens and invites a path error. This server replaces the chain with one atomic operation.

npx file-organizer-mcp --setup

One atomic call

The centerpiece is organize_files(): a single call that runs the whole scan → categorize → plan → move pipeline atomically. If something fails partway, the operation rolls back instead of leaving your Downloads folder half-shuffled. Conflict strategies are explicit: rename, skip, or overwrite with backup, and dry-run previews show the plan before anything moves.

The organization itself is smarter than folder shuffling:

  • 12+ file type categories, with per-type strategies
  • Photos organized by EXIF date into YYYY/MM/DD folders; music by ID3 tags into Artist/Album/Title
  • Duplicate detection via SHA-256 content hashing, scored by location, name quality, and age before you choose what to delete
  • A security-screening workflow that flags sensitive metadata, like GPS coordinates in photos, for redaction

The safety model

Handing an agent filesystem access is the whole point and the whole risk, so the server is paranoid by construction:

  • Whitelist-based directory access; external drives require an explicit allowExternalVolumes opt-in
  • System paths always blocked, with 8-layer path validation, symlink attack protection, and TOCTOU mitigation
  • Resource limits so a runaway agent can't DoS the machine
  • Undo and history tools, so mistakes are reversible

What v5 taught me

v5.0.0 was a ground-up rewrite: stateless MCP protocol, 22 tools, a registry where adding a tool means one file and one line. The interesting lessons weren't about files. They were about shipping: a case-collision bug that ate files, a dead error branch, and required checks pointing at a deleted workflow, all caught in merge week. I wrote the full shipping log in the essays below.

There's also a companion file-organizer-watch daemon for cron-based scheduled organizing, keeping the stdio server itself stateless.

Try it

npm i -g file-organizer-mcp
npx file-organizer-mcp --setup

The setup wizard auto-detects Claude Desktop, Cursor, Windsurf, and Cline. Then just ask your assistant to "organize my Downloads folder". Requires Node.js 18+. Windows, macOS, and Linux.
