Multi-agent coding loops will wreck your git history

Everyone is excited to spin up five autonomous subagents in parallel to refactor a codebase. The reality is that Git was designed in 2005 for humans who read diffs, communicate asynchronously, and think before pushing.

When you let multiple autonomous models edit code concurrently in one repository, you get silent regressions that line-based merge engines cannot detect.

The illusion of clean merges

Git uses three-way line merges. If Agent A touches lines 10 through 25 of a file to refactor an auth method, and Agent B touches lines 80 through 95 to update a database query, Git declares a clean merge without conflicts.

Git does not know that Agent A renamed a session token type, while Agent B introduced a query that relies on the old token interface. Both agents run unit tests in isolation on their branch and report green. When merged, the build breaks, or worse, silently behaves incorrectly at runtime.

The rebase death loop

When agents detect a conflict, the default instinct is to rebase. In practice, here is what happens:

  1. Agent A finishes work on branch feat/cache and pushes to main.
  2. Agent B was halfway through feat/rate-limit. It runs git pull --rebase.
  3. Git pauses on a conflict. Agent B reads the conflict markers and attempts to resolve them.
  4. Because Agent B has a narrow context window, it deletes Agent A's changes to make the local test suite pass.
  5. Agent B force-pushes, completely erasing Agent A's work from the repository history.

This is not a theoretical edge case. It happens constantly in multi-agent swarms.

Intent verification over textual diffs

To run multiple agents safely, we need semantic governance at the version control layer:

  • Intent locks: Agents must declare which symbols, AST nodes, and API contracts they are modifying before generating code.
  • Semantic merge policies: Merges must verify type integrity and AST boundaries, not just line numbers.
  • Audit trails: Every automated merge must record the reasoning and invariants expected by both agents.

This is why I started building Oot. If we are handing repo keys to autonomous models, version control needs to act as a court for code rather than a dumb text patcher.
